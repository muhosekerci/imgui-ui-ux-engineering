# Failure-Mode Regression Cases

Use these cases in addition to `quality-suite.md` when revising the skill or evaluating a model response. They are anonymized, concrete reproductions of recurring practitioner failure patterns; they do **not** claim to represent one identifiable product or user. A passing response must diagnose the root cause, propose a safe corrective pattern, and state a verification method rather than merely describing a more attractive layout.

| ID | Incident-style prompt | Root failure to detect | Minimum passing assertions |
|---|---|---|---|
| F01 — stale filtered view | `My Asset Browser's search box accepts input, but results often remain unchanged until I change sort order. The filtered vector is rebuilt only after clicking a table header.` | UI state changed but the derived filtered/sorted index view was not invalidated. | The response invalidates/rebuilds the derived view on filter, data, and sort-spec changes; does not reorder the source model merely to render a view; defines a no-results state and a reproduction test. |
| F02 — dangling inspector selection | `After an importer refresh, clicking the inspector sometimes edits the wrong asset or crashes. I store Asset* selectedAsset and the importer replaces a std::vector<Asset>.` | A retained pointer becomes invalid after vector replacement/reallocation. | The response stores a stable asset ID in UI state, resolves the live model object at render/action time, handles a missing selection safely, and verifies refresh plus deletion behavior. |
| F03 — collapsed child stack mismatch | `I wrote: if (ImGui::BeginChild("Log")) { DrawLog(); ImGui::EndChild(); } and now DebugCheckVersionAndDataLayout asserts intermittently.` | `EndChild()` is incorrectly conditional on `BeginChild()` returning true. | The response moves `EndChild()` outside the conditional, explains the Begin/End contract, checks other scoped APIs independently, and recommends the bundled checker plus runtime metrics/debug validation. |
| F04 — selection steals navigation focus | `Arrow-key navigation feels broken after I click any asset. I call SetItemDefaultFocus() whenever row.id == selectedAssetId.` | Default focus is asserted every frame instead of on one explicit navigation request. | The response separates pointer selection from programmatic focus transfer, uses a pending stable ID or equivalent one-shot state, preserves keyboard navigation, and tests command-palette selection versus pointer selection. |
| F05 — DPI and status rendering drift | `At 200% DPI, text grows but rows stay cramped. On another monitor it grows again after every theme reload. Status colors are also different between the table and inspector.` | Multiple scale owners/cumulative `ScaleAllSizes()` calls and duplicated hard-coded status colors. | The response resets style before non-cumulative size scaling, selects exactly one owner for `FontScaleDpi`, distinguishes font versus metric scaling, centralizes semantic status tokens, and validates on at least two DPI values. |

## Evaluation protocol

For each failure case, score the answer from 0 to 2. Award `0` when the root cause is absent or the proposed change is unsafe. Award `1` when the diagnosis is correct but either verification or a necessary Dear ImGui implementation detail is missing. Award `2` only when the response satisfies every listed assertion and clearly distinguishes model state, derived view state, and transient UI state where relevant.

A release candidate must earn 10/10 across F01–F05, with no zero. Treat any recommendation that keeps a raw `std::vector` element pointer across a model refresh, conditionally omits a required `End*`, or writes `FontScaleDpi` from two owners as an automatic failure. The executable assertions are maintained in `semantic-cases.json` and run by `scripts/run_semantic_suite.py`.
